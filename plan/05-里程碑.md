## 风险预案

| 风险 | 触发信号 | 预案 |
|---|---|---|
| 上游补齐（fontbakery 加 subset profile） | 上游 release note | 转"下游闸门 + 回归套件"定位，不做正面竞争（`plan/00` 决策②） |
| fontTools 升级导致 golden 漂移 | `gen_fixtures.py --check` 红 | 视为 fixture 迁移事件：逐条复核差异后重生成，`expect.json` 版本号同步 |
| 拿不到 OFL 字体（离线） | `fetch_fonts.py --check` 报 MISSING | 合成 fixture 全可离线；OFL 层显式 `SKIPPED(reason=ofl_fonts_absent)` |
| 许可结论被当法律意见 | 用户提问措辞 | 报告固定声明 + 每条 `spec_ref`；文档不写"可用/不可用" |
| 商用字体红线被破 | 仓库出现 `.ttf` | `.gitignore` 阻断 + 脱敏/布局门之外加一条测试断言 `git ls-files` 无字体二进制 |
| 护城河被高估 | README 文案 | `plan/01` §头部与 README 首屏必须写"技术护城河 ≈ 0"，发布前复查 |

## 已知未验证项

1. ⬜ **CI 实跑**：本仓库目前**无远端**（`git remote -v` 为空），所有 CI 相关 DoD 只能写"本地等价校验"，发布棒首推后据实补记 run id。
2. ⬜ **跨版本行为**：3.12 通道缺 fontTools，本机无法跑"3.12 + fontTools"组合；由 CI 矩阵补。
   （**2026-10-21 M1 更新**：本机已建 `_scratch/v312` venv 装了 fontTools 4.67.0 + pytest 8.4.2，
   两条通道测试全绿；且实测**两版产物二进制逐字节相同**，唯一差异是 `expect.json` 里的版本串 ——
   已改为记录铸造版本常量。CI 矩阵实跑仍未发生。）
3. ⬜ **Arial / Calibri / msyh 的真实行为**：仅本机只读观察（`data/README.md` §四），仓库内以同构 OFL 字体替代，**不得**声称已在仓库复现。
4. ⬜ **`0xFCF1` 保留位掩码**与 fontbakery 的 `0b1111110011110001` 逐字节一致（已核对），但 MS 规范原文的"bits 4–7 / 10–15 reserved"未再二次独立核验（以 `data/README.md` §三为准）。
5. ⬜ **PDF/UA-2 引文**：`pdfa.org` 403，未能核实 → 文档不得引用其文字。
6. ⬜ **`fetch_fonts.py --download` 的稳定性**：本机实测 `raw.githubusercontent.com` 会在传输中重置（单次只拿到 4.5–7.5 MB / 目标 8.3 MB）。脚本走单次请求，网络不稳时**报 `DOWNLOAD_FAILED` 而不写半截文件**（校验在写盘前），但"一次跑通"未验证 —— 本次是外部用 Range 续传脚本补齐的。→ M6 前若要写"`--download` 可用"，必须补一次端到端实测或如实标注。`data/fonts.lock` 里 Inter 走 zip 包、两个 Noto 走 raw 直链。
