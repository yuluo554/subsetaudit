## 一、介绍：痛点与需求证据

**痛点**：子集化是网页字体、PDF 内嵌、App 打包、本地化的标准动作，但**下游拿到的是一份"看起来能装进去"的文件**。三类事故不会在任何一步报错，只会在别人的机器上表现为**缺字、排版错位、许可违规**：

1. **静默丢字**：请求的字符不在字体里，子集器默认不报错、退出码 0，产物里那些字符**直接消失**。下游以为"子集成功了"。
2. **布局被打坏**：GSUB/GPOS 被裁掉或写坏，连字、字距、复杂文种整形失效——产物表还在，规则没了。
3. **许可与元数据**：工具链默认不看 `fsType`（嵌入许可），也默认剥掉许可描述（name ID 13/14）与本地化名称——**产物合法性与可追溯性同时丧失，且此过程无任何提示**。

### 2.2 fontbakery / fontspector 覆盖度结论（三层说，不可一句"占满"或"没占"）

> 本机实测方法：下载 `fonttools/fontbakery` 与 `fonttools/fontspector` main 分支 tarball，直接数 `@check` 与目录。

1. **`fsType` 有检查，但只是"必须等于某个值"，不是"解释成结论"**：
   - `googlefonts/fstype.py`：`if value != 0: yield FAIL`（Google Fonts 要求 Installable）；
   - `microsoft/fstype.py`：`required_value = 8`（Editable）；
   - `profile-fontwerk` 的 `fstype.rs`：要求 Print & Preview（值 4）；
   - `profile-monotype` 的 `fstype.rs`：与期望值比对并给出名称字符串。
   - **没有任何一处把 `fsType` 翻译成"能不能嵌进 PDF / 能不能子集 / 能不能给网页用"**，也没有版本分流。
   - 附带价值：fontbakery 用保留位掩码 `0b1111110011110001`（**= 0xFCF1**，即 bit0 + bits4–7 + bits10–15）判"保留位被置位"，与 MS 规范的保留位定义吻合，可作交叉校验参考。
2. **name 表许可字段有检查，但只认几种开源许可**：`googlefonts/name/license` 的 rationale 明确只接受 **OFL 1.1 / Apache 2.0 / Ubuntu Font Licence 1.0** 三种固定字符串片段；`microsoft/license_description.py` 只校验是否包含**特定 Microsoft 许可文本**。→ **对商用字体（许可纠纷主战场）不适用**。
3. **子集化检查 = 0**：全仓 `subset` 相关只有 5 个 **Google Fonts 元数据**检查（`metadata/includes_production_subsets`、`single_cjk_subset`、`subsets_order`、`unreachable_subsetting`、`unsupported_subsets`），判的是 `METADATA.pb` 的 subsets 声明与 cmap 是否自洽（**整仓源码级复核**：`Lib/fontbakery/checks/` 下 `subset` 命中的 .py 仅此 5 个 + 1 个测试字体），**与"原字体 vs 子集字体"的产物验证毫无关系**；`shaping/regression` 需用户**预先手写** shaping 测试 yaml 才有输入。

**本机实测计数（口径见 `data/README.md` §六，此处只列结果）**：fontbakery `Lib/fontbakery/checks/` 下 `.py` 共 **373** 个，其中 `__init__.py` 45 个；**`@check` 装饰器共 320 个**，其中 `vendorspecific/` **157 个**（googlefonts 112 文件 / microsoft 16 / typenetwork 16 / notofonts 10 / adobefonts 4 / fontwerk 3 / fontbureau 1）。fontspector `profile-universal/src/checks/` 下 `.rs` 共 **79** 个（含 2 个 `mod.rs`）→ **77 个检查模块**。

## 三、任务要求

首期 **5 个模块**，扩展项另列。每模块写清 **输入 / 输出 / 确定性纪律 / 验收**。所有模块共享 `data/README.md` §六的数值口径（`fsType` 判定式、覆盖三分类、退出码、nameID 白名单），不得在代码或文案中另立第二套口径。

### 模块 M1 `license-gate` — 许可闸门

- **输入**：字体文件（原字体或产物）。
- **输出**：`{embed_pdf, embed_app, embed_web, may_subset, may_modify}` 五元结论 + 每条的**规范条款引用**（bit/mask + MS 规范原句） + `os2_version` + `violations[]`（保留位置位、多位并存、非法值）。
- **引擎（规范口径，逐条引用，出处见 `data/README.md` §三）**：
  - bits 0–3（mask **0x000F**）：合法值只有 **0 / 2 / 4 / 8**；**bit0 永久保留必须为 0**；**2 = Restricted License（必须恰好为 2 才生效）**；4 = Preview & Print（文档须**只读**打开）；8 = Editable。
  - **版本分流（必须先读 `OS/2.version` 再判）**：**v0–v2** 规范未要求 bits0–3 互斥，多位同时置位时**取最宽松者**（规范原句 "least-restrictive permission indicated take precedence"）；**v3 及以后**（OpenType 1.4 起）互斥为**强制要求**。→ 不做版本分流会把合法老字体误报为违规。
  - bit8（**0x0100**）= No subsetting；bit9（**0x0200**）= Bitmap embedding only；bits 4–7（**0x00F0**）与 bits 10–15（**0xFC00**）保留必须为 0。
  - 名称字段：name ID **13** = License Description、**14** = License Info URL、**0** = Copyright、**7** = Trademark、**16/17** = Typographic Family/Subfamily、**21/22** = WWS、**25** = Variations PostScript Name Prefix（用于"许可元数据是否还在"的交叉判定）。
- **确定性纪律**：纯读表，不写文件；结论只由 `fsType` + `OS/2.version` + name 表存在性推出；不联网、不查许可证数据库；无法判定的位（未定义组合）走 `notes` + 保守结论（**不猜测意图**）。
- **验收**：① `0x000E` **v0** 字体（权限位 2+4+8 并存）**不得误报**——按最宽松解析为 Editable、`may_subset=true`；② `0x0108` 必须判 `may_subset=false` 且引用 bit8 条款；③ 合成 v3 字体置 `0x000E` 必须报"互斥违规"；④ 保留位置位（bit0）必须单列；⑤ 逐条结论都能回指 MS 规范原句。

### 模块 M2 `coverage-diff` — 覆盖差集

- **输入**：原字体 + 语料（文本文件或 `--text`）+ 可选子集字体。
- **输出**：三分类清单 **`MISSING_IN_SOURCE`（原文缺）/ `LOST_IN_SUBSET`（子集丢）/ `OK`** + 分块统计 + **回退链建议**（`(3,10) → (0,3) → 其它` 取子集可提供的最近似集合）。
- **引擎**：
  - cmap 集合运算，支持 **format 4 / 12 / 13**；**编码优先级 (3,10) → (0,4) → (3,1) → (0,3)**（本机实测：msyh 有 (3,10)/format 12 全 29905 项、(3,1) 29709 项；Arial 只有 (0,3)/(3,1)/format 4；Arial 的 (1,0)/format 0 映射含 **225 项**，其中 **glyph0 命中 225 项**，不得混入 Unicode 判定）。
  - **glyph0 = 缺**：映射到 `.notdef` 的码位不得算作"有覆盖"。
  - CJK 按 **BMP / ExtA / ExtB+** 分块计数；彩色 emoji 按 **COLR+CPAL / sbix / CBDT+CBLC / SVG ** 存在性判定（本机实测 `seguiemj.ttf` 带 `COLR`+`CPAL`）。
  - 语料字符集先做**组合字符闭包**（NFD/NFC 闭包，指向上游 harfbuzz#2283 的同类问题），闭包内缺失单独列计数。
- **确定性纪律**：字符集排序固定（码位升序）；同一输入两次运行输出逐字节一致；不写文件；不修改输入字体。
- **验收**：① **复现** "`pyftsubset --text="汉字abc"` 静默丢汉/字"并判为 `LOST_IN_SUBSET`（**不得判 MISSING_IN_SOURCE**）；② pdfcraft#381 那组字（`绪 顺 导 选 单 钮 图 签 存 护 码 离 需 账 务 全 处 页 区 块 转 突 划 线 删 旋 释 馈 获`）构造"按词表切"的子集，能复现"高频字在、中频字缺"的指纹；③ 只有 (1,0)/format 0 映射的字体必须走显式 `SKIPPED(reason=no_unicode_cmap)`，不静默得出"覆盖为空"。

### 模块 M3 `layout-survival` — 布局保真

- **输入**：原字体 + 子集字体。
- **输出**：丢失的 `(script, langsys, featureTag)` 三元组清单；**涉及必需字符的连字规则清单**（规则涉及的字符都在需求字符集内）；lookup 计数（原始 / 保留）。
- **引擎**：GSUB/GPOS Header → **ScriptList → FeatureList → LookupList（+ FeatureVariations）**；**LookupType 7（Extension）必须解包 `ExtSubTable`**（否则整棵子树读不到，本机实测 Arial 报告 **0 vs 784**）；lookup 顺序语义（同一 feature 内 lookup 顺序影响结果，重排必须报）。
- **确定性纪律**：只读；三元组与规则清单按稳定键排序；不推断"作者意图"，只报"原字体有、产物没有"。
- **验收**：① Arial 原字体解包后**正确计数 784 条连字规则**（朴素遍历 0 条 → 必须由本工具给出 784）；② Calibri 默认子集必须列出被丢弃标签（`ss01`–`ss08`、`case`、`tnum` 等），并列出 `liga` 存活但目标字形已改名（`uniFB01 → glyph00003`）；③ 三元组丢失在 `--layout-features=''` 产物上全量复现。

### 模块 M4 `metadata` — 元数据与位域一致性

- **输入**：子集字体（可选原字体用于差分）。
- **输出**：许可元数据存活报告（name ID **0/7/11/13/14/16/17**）+ OS/2 位域**自洽性**报告 + 与 cmap 的一致性判定。
- **引擎**：
  - **name**：默认 `name_IDs=[0..6]` 会剥掉 13/14；`name_languages` 默认仅 `[1033]` → 非英文记录被裁（本机 msyh：26 languageID → 1）。
  - **OS/2 ↔ cmap 一致性**：`ulUnicodeRange*` 是否覆盖 cmap 实际用到的块；`ulCodePageRange*` 是否声称了 cmap 里根本没有的码页。**判定必须按位与 cmap 实测集合比对，不得只比"是否为 0"**。
  - **`prune_unicode_ranges` 默认 True** 会重算 `ulUnicodeRange*`（本机实测重算结果**正确**：bit59 置位）；**`prune_codepage_ranges` 默认 True** 会在无码页可用时**回退置 bit0（Latin 1）**——这是真实自相矛盾点。
  - `maxp.numGlyphs` vs 实际字形数；`usFirstCharIndex`/`usLastCharIndex` 与 cmap 范围一致性。
- **确定性纪律**：只读；所有结论给出"位值 + cmap 证据 + 判定式"；同一产物两次运行一致。
- **验收**：① msyh 仅子集"汉字"后 `ulCodePageRange1 = 0x1` 而 cmap 无任何 Latin-1 字符 → **必须报"码页声明与 cmap 矛盾"**；② **不得**把"`ulUnicodeRange1 = 0x0` 而 cmap 有汉字"报成矛盾（实测 `ulUnicodeRange2` bit59 已正确置位）；③ 缺 nameID 13/14 必须单列并按"默认剥离"与"原作者就没写"分两类（用可选原字体差分区分）；④ `maxp.numGlyphs == 实际字形数` 时不得报发现。

### 模块 M5 `report` — 报告与 CI 契约

- **输入**：M1–M4 的原始结果。
- **输出**：规范 JSON（`findings[]` + `summary` + `inputs`）或 Markdown 摘要（仅渲染视图，不参与 digest）；**退出码 0 = 通过 / 1 = 有发现 / 2 = 输入非法**（不可读、非字体、缺必需参数）。
- **引擎**：finding 带上 `module`、`severity`（`error`/`warn`/`note`）、`evidence`（位值或码位集合或三元组）与 `spec_ref`（条款引用）；`SKIPPED(reason=...)` 必须出现在输出里而不是只写日志，且**不影响退出码**。
- **确定性纪律**：不写扫描时刻/绝对路径/主机名/用户名；键序固定；排序键固定（`module, severity, 主键`）。
- **验收**：① 三档退出码各有 fixture；② 输入目录里夹一个非字体文件 → 退出码 2 且指明文件；③ 同一输入两次运行 JSON 逐字节一致；④ 每个 `error` 都能回指 `spec_ref` 或实测证据。

## 七、边界与非目标

- **不做可变字体轴 / STAT 审计**：fontbakery 已有 11+ 项（`fvar/axis_ranges_correct`、`inconsistencies_between_fvar_STAT`、`mandatory_avar_table`、`STAT_axis_record_for_each_axis`、`layout_valid_feature_tags` 等），fontspector 再叠数项；本机实测 fontTools 子集对 `fvar/STAT/avar/MVAR/HVAR/gvar` 保留正确 → **重写 = 抄**。
- **不做字体许可合规扫描器**：扫描项目/域名/PDF 里的字体引用属于合规审计类禁区（要联网、要判"使用是否合规"），且已有 fontsentry（2★）、FontGuard（0★）、fontcheck（0★）一类的同类项目。本工具只回答"这份字体的 `fsType` 允许什么"（单文件、可复算）。
- **不做 PDF 内嵌字体检查器**：与"PDF 解析 + 许可证判断"邻域重叠，输入形状也不是"原字体 + 产物 + 需求"。
- **不做子集生成器**：subfont 1636★ / glyphhanger 1123★ / fontmin 6220★ / font-spider 5140★ 红海；且生成器与校验器共用一套口径会丧失独立性。
- **不做轮廓几何 / hinting / 渲染视觉比对**：见 §三扩展项表。
- **绝不入库商用字体**：Windows / Monotype / 任何商用字体一律**只读不复制不分发**；仓库不出现 `.ttf/.otf/.ttc` 二进制（`.gitignore` 强制），fixture 与回归只用 OFL 字体或程序合成的极小字体，且以 URL + 字节数 + sha256 记录（`data/fonts.lock`）。
- **隐私红线**：纯本地、零网络（仅在用户显式运行 `tools/fetch_fonts.py` 时联网下载，且默认 `--check` 只校验已有文件）。
- **品牌隔离**：本题是"字体产物审计"，文档与代码中**不提名本系列其他项目或其他仓库**。
- **首期范围限定**：`SKIPPED(reason=...)`（无 Unicode cmap、无 GSUB/GPOS、CFF/CFF2 轮廓相关的深层判定）**显式记录、不静默漏报、不影响退出码**；扩展项不进首期判定路径。
- **结论纪律**：所有发现是"输入与产物之间的**可复算差异**"，不等于"这条字体不能上线"；报告必须同时给出位值/码位集合/三元组证据，由人判断业务影响。`fsType` 判定是**技术性结论（规范怎么读）**，不是**法律意见**。

## 八、与被复制风险的应对（如实登记）

- **风险**：fontbakery 若加一个 subset profile，或 fontspector 的 Rust 检查框架直接补一个 `--subset-audit`，二者三个月内可覆盖 M2/M3/M4 的大部分判定。
- **已知防守**：输入形状（原字体 + 产物 + 需求，退出码面向 CI 下游）与它们的输入形状（字体项目 / 源文件）不同；规则集与 fixture 库是本题可积累的资产；`OS/2.version` 分流的 fsType 解释器是它们目前**没有**的（它们只比对常值）。
- **诚实结论**：本题的价值在**规则集与 fixture 库的沉淀**与**下游集成点的定义**，不在代码量。若上游补齐，本题应转为"下游闸门 + 回归套件"定位，而不是坚持"我们是唯一实现"。
